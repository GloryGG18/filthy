# Filthy Tickets: Telegram Mini App

MVP квиткового застосунку для вечірок Filthy (@filthy.sk): анонси, купівля квитків, знижка за репост, оплата PAY by square і банкою monobank, QR-вхід, продаж на місці і звірка каси.

## Стек

- **Node.js 22** (вбудований SQLite `node:sqlite`, без нативних залежностей), **Fastify** для API, **grammY** для бота.
- **Mini App** на чистому JS без збірки (`public/`): відкривається з бота, мови UA / RU / EN.
- Одна база-файл `data/filthy.db`, скріншоти й афіші в `data/uploads/`. Для однієї вечірки на кілька сотень гостей цього вистачає з запасом.

## Що вміє

| Роль | Функції |
|---|---|
| Гість | Список вечірок, тарифи 10 € онлайн / 8 € з репостом / 12 € на вході (довідково), бронь на 30 хв, оплата PAY by square або monobank, «Мої квитки» з QR, сповіщення в боті про оплату і нагадування в день події |
| Репост 8 € | Гість вантажить 2 скріншоти (сторіс з відміткою і профіль з підписниками), адмін схвалює одним дотиком у чаті бота або в адмінці, і лише тоді відкривається оплата 8 € |
| Контролер | Сканер QR (нативний сканер Telegram), повноекранний результат: зелений «Оплачено», червоний «Вже використано о 23:14 / Недійсний / Інша вечірка», жовтий «Не оплачено»; ручне введення номера; продаж на вході «Готівка / Картка» з сумою; лічильник входів |
| Адмін | Події й афіші, розсилка анонсу всім підписникам бота, черга репостів, платежі на ручну перевірку (недоплата, без номера, дубль), пошук квитка і «позначити оплаченим», призначення контролерів, звіт по касі з розбивкою по контролерах, внесення порахованої готівки і різниця, CSV у чат з ботом |

### Як працює оплата

- **PAY by square.** Квиток має 8-значний номер, він же варіабільний символ. Застосунок показує QR з IBAN, сумою і VS. Бекенд кожні 30 с читає виписку рахунку і активує квиток, якщо сума ≥ ціни. Платежі, що прийшли після закінчення броні, все одно зараховуються (гроші не губляться).
- **monobank.** Сума в гривнях фіксується за курсом monobank у момент вибору оплати. Гість платить у банку з номером квитка в коментарі. Вебхук monobank (плюс резервне опитування виписки раз на 10 хв) активує квиток, якщо сума ≥ 98 % очікуваної; менше потрапляє адміну на перевірку.
- **monobank, режим «картка».** Сторінка банки показує всім зібрану суму, тому в адмінці можна перемкнути «Как гости платят» на переказ на картку. Гість обовʼязково пише в коментарі номер квитка (застосунок це помітно показує), і бекенд знаходить переказ за ним. Про запас кожен квиток ще й має свою суму з копійками (наприклад 487,13 ₴), тож переказ знайдеться навіть тоді, коли коментар загубився. Інші надходження на картку ігноруються. Потрібно вказати номер картки і вибрати її через «Найти мои банки и карты».
- **Захист QR.** У коді `FLT:<номер>:<HMAC-підпис>`, тому підробити не вийде; після першого сканування квиток «використаний», а одночасне сканування двома контролерами не пропустить двох людей.

## Запуск локально

```bash
npm install
cp .env.example .env      # для локальної перевірки: DEV_AUTH=1, ADMIN_IDS=1
npm run seed              # дві демо-вечірки
npm run dev
```

Відкрити в браузері `http://localhost:3000/?dev=1` (адмін) або `?dev=2` (гість). Імітувати надходження переказу:

```bash
curl -X POST localhost:3000/api/dev/payment -H 'content-type: application/json' \
  -d '{"source":"fio","amount":1000,"currency":"EUR","reference":"<номер квитка>"}'
```

Тести всього сценарію (покупка, репост, обидві оплати, сканування, каса, ліміт місць): `npm test`.

## Запуск у Telegram

1. Створити бота в @BotFather, взяти `BOT_TOKEN`. Там же `/newapp` (або Bot Settings → Menu Button) з адресою `PUBLIC_URL`.
2. Розгорнути на сервері з https (будь-який VPS, Fly.io, Railway, Render; є `Dockerfile`, том `/data` для бази). Заповнити `.env` за зразком `.env.example`.
3. Написати боту `/start`, потім `/id` і вписати свій ID у `ADMIN_IDS`. Для групи адмінів: додати бота в групу, `/id` у групі дасть `ADMIN_CHAT_ID`.
4. Контролерам: хай один раз відкриють бота, а адмін додасть їх у «Команда» за @username.

При https-адресі бот сам ставить вебхук Telegram, кнопку меню з Mini App і вебхук monobank.

## Що треба від організатора перед першою вечіркою

- **Рахунок для PAY by square** (IBAN фірми або живності) і доступ до виписки через API. Адаптер Tatra banka в `src/payments/bank.js` поки заглушка: потрібна реєстрація застосунку на developer.tatrabanka.sk і дані доступу, тоді його допишемо. Fio banka працює вже зараз (токен з інтернет-банкінгу, `BANK_PROVIDER=fio`). Без API можна стартувати з `BANK_PROVIDER=none` і підтверджувати перекази вручну в адмінці.
- **monobank**: токен з api.monobank.ua від власника банки, ID банки і посилання на неї.
  - Як отримати токен: власник банки відкриває api.monobank.ua, сканує QR (або тисне посилання з телефона) і підтверджує вхід у застосунку monobank; сторінка покаже токен. Його вставляють в адмінці → «Оплата» → monobank, потім «Знайти мої банки». Посилання для гостей: у застосунку банка → «Поділитися». Токен дає лише перегляд виписки, відкликати його можна там само. Ця ж інструкція є в адмінці під «Где взять токен?».
- Бренд: колір акценту і шрифт задаються змінними на початку `public/style.css`.

## Налаштування оплати з адмінки

Адмін → «Оплата»: IBAN, BIC і отримувач для PAY by square, джерело виписки (вимкнено / Fio / Tatra) і його ключі, токен monobank, банка (кнопка «Знайти мої банки» підтягує ID і посилання) та допуск по курсу. Зміни діють одразу, без перезапуску, і мають пріоритет над `.env`. Ключі після збереження ніколи не показуються в інтерфейсі повністю; порожнє поле означає «не змінювати», ✕ видаляє ключ. Значення зберігаються в базі на сервері, тому доступ до сервера і бекапів бази треба тримати закритим.

## Структура

```
src/
  index.js        запуск сервера, бота і фонових задач (зняття броні, виписка, нагадування)
  server.js       HTTP API
  tickets.js      квитки, бронь, зарахування платежів, сканування, продаж на вході, звіт
  repost.js       скріншоти і схвалення репостів
  bot.js          бот: /start, схвалення в один дотик, сповіщення, розсилка, CSV, нагадування
  auth.js         перевірка підпису Telegram initData, ролі
  settings.js     налаштування оплати, які адмін змінює в застосунку
  payments/       PAY by square, monobank, виписка банку (Fio / Tatra)
public/           Mini App
test/             наскрізний тест
```

## Деплой на Railway

1. Новий проєкт → Deploy from GitHub repo → цей репозиторій (збирається з `Dockerfile`).
2. Settings → Networking → **Generate Domain** (порт 3000). Адресу застосунок візьме сам.
3. **+ Add → Volume**, прикріпити до сервісу (точка монтування будь-яка, наприклад `/data`); застосунок сам знайде шлях.
4. Variables: достатньо одного `BOT_TOKEN`. Заглушки з `.env.example` ігноруються, `QR_SECRET` генерується і зберігається на томі, а адміном стає перша людина, що напише боту `/start` (якщо `ADMIN_IDS` не задано).
